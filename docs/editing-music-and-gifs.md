# Swapping tracks and gifs

Everything below is a one-line edit or a one-command run. Nothing needs a build
step and nothing needs to be regenerated by hand.

---

## 1. A track on the music page

**File:** [`js/data/tracks.js`](../js/data/tracks.js)

Find the track and change `videoId`:

```js
{ id: 'blessings', videoId: '2lmPm_yZ9Ow', art: 'borrowed' },
```

Paste whatever shape of link you have. All three of these are the same thing:

```js
videoId: 'https://www.youtube.com/watch?v=2lmPm_yZ9Ow'
videoId: 'https://youtu.be/2lmPm_yZ9Ow'
videoId: '2lmPm_yZ9Ow'
```

The order of the list is the order of the tracklist. To reorder, move the line.
To remove a track, delete the line and its copy in `js/i18n/music.js`.

### Adding a new track

Two edits, because every string on the site exists in both languages:

1. Add a line to `TRACKS` with a new `id` and an `art` value
   (`melody`, `pedal` or `borrowed` — that is the little drawing on the cover).
2. Add `track.<id>.title` and `track.<id>.credit` to **both** the `en` and
   `fr` blocks of [`js/i18n/music.js`](../js/i18n/music.js). For a track with
   `id: 'blessings'` those keys are `track.blessings.title` and
   `track.blessings.credit`.

`npm run check:i18n` will tell you if you forgot one.

## 2. A track on the secret page

**File:** [`js/data/letters.js`](../js/data/letters.js)

One line per composer. Change `video`:

```js
{ id: 'call', composer: 'Evan Call', video: '' },
```

becomes

```js
{ id: 'call', composer: 'Evan Call', video: 'https://www.youtube.com/watch?v=XXXXXXXXXXX' },
```

Then run:

```
npm run thumbs
```

That fetches the video's own thumbnail into `assets/thumbs/<id>.jpg`, which is
what the letter shows before you press play. Keeping our own copy rather than
pointing at Google is what lets the page contact nobody until somebody clicks.
It only fetches what is missing; add `--force` to redo the lot.

You **do not need to know whether the video allows playing outside YouTube.**
The page tries to play it, and if YouTube refuses, that letter turns itself into
a "Listen on YouTube" button over the same thumbnail. Leave `video` empty and
the letter renders quietly without a player.

### The one rule worth keeping

Link the **rightsholder's own upload**, not a fan re-upload. Embedding somebody
else's copy is the one case where it stops being protected. In practice, look
for one of:

- the composer's own channel
- a channel ending in `- Topic` (those are generated by the label)
- the label or studio channel

If the only copy you can find is on a channel called something like
`AnimeOST4Ever`, leave the field empty rather than link it.

## 3. A gif on the secret page

**Folder:** `assets/gifs/`

The six are `floor`, `glass`, `gymnast`, `whiteboard`, `cottage` and `piano`.

1. Save your new gif over the old one, keeping the same name.
   For example, replace `assets/gifs/piano.gif`.
2. Run:

   ```
   npm run gifs
   ```

That is it. The script rebuilds the still frame beside it (the `.png`, shown to
anyone whose system asks for reduced motion) and writes the gif's real width and
height back into `the-color-i-was-chasing.html`, so the page does not jump
around while it loads.

Where each one came from is recorded in
[`assets/gifs/SOURCES.md`](../assets/gifs/SOURCES.md) — worth updating when you
swap one, since the page credits them.

### Getting a gif off Giphy

Giphy serves a placeholder image to anything that does not look like a browser,
so right-click and Save Image from a normal browser tab. If the file you end up
with is exactly **239,321 bytes**, that is the placeholder, not the gif. The
test suite checks for this so it cannot ship by accident.

Keep them under roughly 800 KB. `npm run gifs` prints each file's size.

### Changing a caption

Captions live in [`js/i18n/color.js`](../js/i18n/color.js) under
`c.scene.floor`, `c.scene.glass`, and so on. Both languages, as always.

## 4. Writing the words

**Files:** [`js/i18n/color.js`](../js/i18n/color.js) (the secret page),
[`js/i18n/music.js`](../js/i18n/music.js) (the music page)

Prose is written in blocks. Break the lines wherever they read best; only a
**blank line** starts a new paragraph, and nothing else about your line breaks
reaches the page.

```js
// Beside the flopped-cat gif.
'c.floor': p`
  You know that feeling when you cook something, you follow the recipe
  exactly, and it still tastes like nothing. That.

  So I did what any reasonable person does at midnight.
`,
```

That renders as two paragraphs. Rewrap it, split a sentence over three lines,
add a line break mid-thought because it reads better in the editor: the page
does not change.

Two tags, and the difference is only which one the page expects:

| tag | for | gives |
|---|---|---|
| `` p`…` `` | prose | paragraphs, one `<p>` per block |
| `` one`…` `` | titles, captions, buttons, labels | a single run of text |

A comment above each key says where it appears on the page, so you can find the
bit you want without loading the site.

**Apostrophes need no escaping.** These are backtick templates, so write
`it isn't` and `l'ambition` directly. The one character that does need care is
a literal backtick, which has to be written `` \` `` — the only place that
comes up is inside a kaomoji like `` (´；ω；\`) ``.

Inline markup passes straight through: `<em>`, `<strong>`, and
`<span class="kao">(◕‿◕)</span>` all work.

Every key exists twice, once under `en:` and once under `fr:`. `npm run check:i18n`
fails if you add one and forget the other.

## 5. Checking which links actually play

Not every YouTube video is allowed to play outside YouTube, and you cannot tell
from the link. With the site running, open:

    http://127.0.0.1:8000/tools/check-embeds.html

It tries every link in `letters.js` and reports each as **plays in page**,
**links out**, or **no link yet**. Both of the first two are fine; a letter that
links out shows a "Listen on YouTube" button instead of a player. Use it when
you swap links and want to know what you are getting.

## 6. After any change

```
npm run verify
```

If you changed a link, `npm run thumbs` first. If you changed a gif,
`npm run gifs` first. Both are safe to run at any time.


That runs the contrast check, the English/French parity check, and the tests.
It is fast, and it catches the two mistakes that are easy to make: a string
added in one language only, and a gif whose declared size no longer matches
the file.

To look at it, `npm run serve` and open <http://127.0.0.1:8000>, or use the
VS Code Live Preview extension.

> **If a change does not show up in the browser**, it is the module cache, not
> your edit. Hard-reload with Ctrl+Shift+R. Live Preview usually handles this
> for you.
